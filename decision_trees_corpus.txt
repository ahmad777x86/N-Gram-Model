Decision trees are non-linear supervised learning models that partition the feature space into regions to make predictions, either for classification (predicting discrete labels) or regression (predicting continuous values). They work by recursively splitting the data based on feature thresholds, creating a tree-like structure where internal nodes represent decisions, branches represent outcomes, and leaves represent predictions.
Decision trees use greedy, top-down recursive partitioning to divide the input space into homogeneous regions, minimizing a loss function at each split. This approach is intuitive, like playing "20 Questions" with data.
Easy to explain and interpret (visualizable as trees), handle both categorical and continuous features, fast training and inference, and non-parametric (no assumptions about data distribution).
Prone to overfitting (high variance), poor at capturing additive structures (e.g., linear relationships like x1 = x2), and often lower predictive accuracy compared to ensembles.
Can be adapted for regression (predicting means) or classification (predicting majority class). Regularization prevents overfitting, and ensembles (e.g., random forests) address variance issues.
While powerful for simple datasets, decision trees alone may not capture complex interactions without deeper trees or ensembles; evidence from machine learning practice suggests they excel when combined with methods like bagging or boosting.
Decision trees are widely used in scenarios requiring interpretability, such as medical diagnosis (e.g., splitting on symptoms) or financial risk assessment (e.g., splitting on credit scores). They form the basis for more advanced models in libraries like scikit-learn.
A decision tree partitions the feature space X into M regions (R_1, R_2, ..., R_M). For classification, predict the majority class in each region; for regression, predict the mean value.
At each node, select feature j and threshold t to minimize loss: R_1 = {X | X_j <= t}, R_2 = {X | X_j > t}.
Supporting resources: For implementation, refer to scikit-learn's DecisionTreeClassifier/Regressor (https://scikit-learn.org/stable/modules/tree.html). The concepts here are drawn from classical machine learning theory, with practical examples in datasets like Iris or Boston Housing.
In-Depth Notes on Decision Trees
This comprehensive guide synthesizes key principles of decision trees, drawing from foundational machine learning concepts. It emphasizes advanced aspects such as split criteria optimization, handling of different data types, regularization strategies, and performance analysis. Decision trees are a cornerstone of non-parametric modeling, offering a balance between simplicity and flexibility, though they benefit greatly from ensemble extensions for real-world applications.
Fundamentals
1. Motivation and Non-Linear Modeling
Decision trees address limitations of linear models (e.g., SVMs, logistic regression) by enabling non-linear decision boundaries. Linear classifiers struggle with datasets where classes are separated in complex, region-based patterns.
Example: Skiing Classifier: Consider a binary classification task predicting if skiing is possible based on time (month, x-axis: 1=January to 12=December) and location (latitude, y-axis: +90 degrees North Pole, 0 degrees Equator, -90 degrees South Pole). Northern Hemisphere: Skiable in early months (winter positives), not in later months. Southern Hemisphere: Skiable in mid-year (flipped seasons). Equator: Generally not skiable (negatives). A linear boundary fails to isolate these regions effectively, but decision trees partition the space naturally (e.g., first split on latitude > 30 degrees, then on month < 3). This illustrates how decision trees "carve" the feature space into interpretable regions, unlike kernel tricks in SVMs which project to higher dimensions but lack direct interpretability.
2. Recursive Partitioning Algorithm
Decision trees build via a greedy, top-down recursive process, starting from the full feature space and splitting until stopping criteria are met.
Formal Definition:
Start with parent region R_p.
Find split s_p = (j, t) where (j) is the feature index and (t) is the threshold.
Child regions: R_1 = {X in R_p | X_j <= t}, R_2 = {X in R_p | X_j > t}.
Recurse on (R_1) and (R_2).
Greedy Optimization: At each step, choose the split that maximizes information gain (or minimizes loss). This is computationally tractable but not globally optimal, as finding the absolute best partitioning is NP-hard.
Prediction:
Classification: Majority vote in leaf region.
Regression: Mean of target values in leaf.
3. Split Criteria: Measuring Purity
Splits aim to create "pure" regions (homogeneous/same in class or value). Common losses include:
Misclassification Loss: L(R) = 1 - max_c p_c, where p_c is the proportion of class (c) in region (R).
Intuitive but insensitive: Doesn't reward splits that isolate minorities better (e.g., splitting 900 positives/100 negatives into 700/100 and 200/0 yields same loss as 400/100 and 500/0, despite the latter being better).
Cross-Entropy Loss (Information Gain): L(R) = - sum_c p_c log_2 p_c.
Borrowed from information theory: Measures "bits" needed to encode class given probabilities.
Strictly concave, ensuring splits always reduce loss (gain > 0 unless identical regions).
Preferred over misclassification for sensitivity to distribution shifts.
Gini Impurity: L(R) = sum_c p_c (1 - p_c).
Similar concave shape to cross-entropy; computationally efficient.
Equivalent to expected error if predicting randomly based on class proportions.
Gain Calculation: Maximize delta L = L(R_p) - [L(R_1) + L(R_2)], or equivalently minimize weighted child losses.
Criterion Formula Pros Cons Use Case
Misclassification 1 - max_c p_c Simple Insensitive to subtle improvements Basic binary tasks
Cross-Entropy - sum_c p_c log_2 p_c High sensitivity, theoretical basis Slightly more compute Multi-class, imbalanced data
Gini sum_c p_c (1 - p_c) Fast, similar to cross-entropy Less interpretable as "bits" General classification
Geometric Insight: Plot loss vs. proportion of positives (binary case). Concave functions ensure the average child loss is below parent loss, promoting meaningful splits.
4. Regression Trees
Extend classification to continuous targets (e.g., predicting snowfall inches instead of skiable yes/no).
Prediction: Leaf predicts mean y_m = (1 / |R_m|) * sum_{i in R_m} y_i.
Loss: Squared error L(R_m) = (1 / |R_m|) * sum_{i in R_m} (y_i - y_m)^2.
Splits: Same partitioning, but minimize variance reduction (analogous to information gain).
This creates piecewise constant approximations, effective for non-linear regressions without assuming functional forms.
Implementation Details and Refinement
1. Handling Categorical Variables
Decision trees natively support categoricals without one-hot encoding.
Split: For (q) categories, consider subsets (e.g., "Is location in {Northern Hemisphere}?").
Complexity: 2^q possible splits, so limit (q) (e.g., <10). For binary classification, sort categories by positive proportion and scan linearly for efficiency.
2. Regularization to Prevent Overfitting
Decision trees can overfit by growing until one example per leaf (high variance).
Heuristics: Minimum leaf size (e.g., stop if <5 examples). Maximum depth or nodes. Avoid minimum loss decrease (misses higher-order interactions; e.g., latitude split alone is weak, but combined with month is strong).
Pruning: Grow full tree, then remove nodes bottom-up using validation set misclassification error. Cost-complexity pruning balances accuracy and tree size.
3. Runtime Analysis
Training: O(n f d), where (n) = examples, (f) = features, (d) = depth (often <= log n). Each example visits (O(d)) nodes; per node, evaluate (O(f)) features (brute-force for binaries, sort-and-scan for continuous).
Inference: O(d), extremely fast.
Scalable: Processes data matrix (n x f) only O(d) times.
Model Context and Future Directions
1. Advantages and Disadvantages
Pros: Interpretable: Visual trees reveal feature importance. Handles mixed data types. Fast: Suitable for large datasets.
Cons: High variance: Sensitive to small data changes. Poor on additive structures (e.g., requires many splits to approximate (x_1 = x_2)). Low standalone accuracy: Often outperformed by ensembles.
In practice, decision trees shine as "weak learners" in ensembles, addressing their limitations while retaining interpretability.
2. Advanced Considerations
Feature Importance: Measured by total loss reduction across splits involving the feature.
Surrogate Splits: Handle missing values by using correlated features.
Multi-Output: Predict multiple targets simultaneously.
Limitations in High Dimensions: Curse of dimensionality; mitigate with feature selection.
